## General Rules

1. Inspect the repository before making changes.
2. Follow the documented architecture.
3. Do not modify unrelated functionality.
4. Do not introduce unnecessary dependencies.
5. Do not hardcode secrets.
6. Use existing components when possible.
7. Keep the UI responsive.
8. Prioritize P0 requirements.
9. Run the application after significant changes.
10. Fix errors before considering the task complete.

## Competition Rule

The project is being developed under a strict time limit.

Prefer:
- Simple
- Reliable
- Demonstrable
- Visually polished

over:
- Over-engineered
- Complex
- Theoretically scalable but unfinished

## Priority

P0 = Must work

P1 = Important

P2 = Nice to have

Always finish P0 before spending significant time on P1 or P2.
